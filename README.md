# 地毯首图生产平台

师嘉文 · AI 产品作品集项目

把商品素材、场景参考与首图制作组织成一条生产流程。

**先查看：** [直接演示](https://jia-wen-shi.github.io/demos/carpet/) · [项目案例](https://jia-wen-shi.github.io/#case-carpet) · [作品集首页](https://jia-wen-shi.github.io/)

## 项目背景与职责

需求来自天津地毯电商。原来的找图、链接数据分析与制作分开进行：选参考，再交给设计师。项目让运营可以直接制作已有商品的场景主图，帮助买家理解地毯的应用场景与家居风格搭配；纯原创商品链接仍由设计师制作。

运营事先准备商品与竞品参考，这部分不在本次功能处理范围。商品原图提供颜色、材质与图案依据，参考用于场景、搭配与构图。尺寸比例可以定制，并非本场景主要问题。

我的职责：需求与流程梳理、产品方案、前端与交互，使用 Codex 和 Superpowers 辅助开发；后端功能由技术方开发。

核心目标：理解设计与生成技术的能力边界，根据业务场景进行技术选型，通过 AI 辅助开发验证产品方案，并控制质量、成本和风险。

## 流程与技术判断

1. 从运营已经备好的商品与竞品参考开始；上游找图与流量判断保持人工处理。
2. 一套业务操作涉及三个角度的场景图，最后完成地毯商品图与场景融合，中间可以反复生成并筛选。当前工程接口以商品图、单张场景参考与修改要求生成一张候选，不将三角度业务流程写成已验证的自动批量生成。
3. 通过 Codex 和 Superpowers 推进前端，检查手动提示词保留、模板重置、任务状态和候选选择；传统 3ds Max、Photoshop、ComfyUI / Redux 经验用于判断任务约束，不作为当前后端依赖。
4. 文件有效性由工程校验，商品信息、场景与搭配继续人工检查。选定主图后，其余内容沿用之前的素材图片。

## 买断交付与制作参考

2026 年 5 月启动，开发约一个月；主图生成功能向天津前老板一次性买断交付，已收款、对方已使用。后续没有持续回访，我自行对平台做过小幅优化，基础功能与框架保持一致。SKU、详情页和后续数据相关能力不计作当前交付。

以下由本人补充的使用口径整理，未取得对方 API 账户的完整账单或后台统计：

| 项目 | 本人提供的参考 | 范围 |
| --- | --- | --- |
| 传统渲染 | 最低 100 元 / 套 | 一套三张的报价 |
| 当前时间 | 5–8 分钟 / 套 | 整套生成与筛选；运营提前准备的商品与竞品参考不计入 |
| 图像接口 | 约 0.5 元 / 次 | 一次调用的费用；反复生成时需计入所有调用 |

传统整套报价与 API 单次费用的范围不同，不能直接计算降本百分比。完整制作成本应包含全部生成、重试与人工工作。参考链接的已有流量是选参考的依据，未取得新主图的点击率、转化率或流量提升数据。

## 本地运行

需要 Node.js 24、pnpm 10、自行配置的 Supabase 数据库/存储和图像模型服务。

```bash
npx pnpm@10 install --frozen-lockfile
# 将 .env.example 复制为 .env.local，填写自己的服务配置
npx pnpm@10 dev:full
```

前端默认 4173，API 默认 4174。数据库结构见 `supabase/migrations/`。模型生成会访问配置的服务，公共案例页面不执行生成。现有测试：`npx pnpm@10 test`。
