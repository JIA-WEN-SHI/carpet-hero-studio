# 地毯首图生产平台

当前版本接通了“产品图 + 单张场景参考图 → JMR `gpt-image-2` → 单张候选首图”的完整前后端流程。

## 环境要求

- Node.js 20 或更高版本
- pnpm
- Supabase 项目
- JMR API Key

## 1. 配置 Supabase

在 Supabase SQL Editor 中运行：

```text
supabase/migrations/202607030001_scene_generation.sql
```

迁移会创建业务表、默认提示词模板和私有 Storage Bucket `carpet-assets`。

## 2. 配置本地环境

复制 `.env.example` 为 `.env.local`，填写：

```dotenv
JMR_API_KEY=你的JMR密钥
JMR_BASE_URL=https://jmrai.net/v1
JMR_IMAGE_COST_POINTS=2.8
JMR_PROXY_URL=
SUPABASE_URL=https://你的项目.supabase.co
SUPABASE_SECRET_KEY=你的sb_secret密钥
SUPABASE_STORAGE_BUCKET=carpet-assets
API_PORT=4174
ENABLE_JMR_CONTRACT_TEST=false
```

`JMR_API_KEY` 和 `SUPABASE_SECRET_KEY` 只能保存在后端环境变量中。不得改名为 `VITE_*`，不得放入浏览器代码或 Git。

如果 Windows 已开启系统代理，一键启动脚本会自动读取并传给后端。也可以手动设置 `JMR_PROXY_URL=http://127.0.0.1:端口`。

## 3. 上传三个推荐场景

仓库已经包含三张无文字默认场景。Supabase 配置完成后运行：

```powershell
pnpm seed:scenes --check
pnpm seed:scenes
```

可以用同名 1:1 PNG 替换 `seed/scenes/` 中的默认图片，再重新建立场景数据。

## 4. 启动

双击：

```text
一键打开首图平台.cmd
```

或在终端运行：

```powershell
pnpm dev:full
```

前端地址：`http://127.0.0.1:4173/`

API 健康检查：`http://127.0.0.1:4174/api/health`

## 展示案例与假数据

仅展示流程时，在当前项目目录运行 `pnpm dev`，打开 `http://127.0.0.1:4173/?demo=1`。
根地址也默认进入演示，点击“退出演示”可切换至真实接口工作台（`?demo=0`）。

选品项目仅展示“33 · 自有SKU”，产品图来自 `33/自己slku/自己slku`，包含四款自有地毯平面样式。已移除顶部介绍横幅、案例切换栏和“深古木”项目卡片。旧案例素材及本地记录保留，不再作为默认项目或完成作品展示。

33 的展示流程：上传 / 选择原主图作为画面参考 → 第二步选择并确认自己的 SKU 产品图 → 沿用第一步主图的深浅风格 → 编辑场景生成提示词 → “生成场景” → 查看生成结果 → “采用场景，进入融合” → 编辑地毯融合提示词 → “模拟融合一张” → 首图交付 → “完成并保存首图”。

场景有独立的约 4 秒生成演示：准备三个角度的构图 → 统一家具与周边陈设 → 调整光线、整理三张无字场景。点击一次生成当前深浅方案的三个场景。每种风格六张、分两批：首次显示第1–3张，重新生成显示第4–6张，再点则循环回第1–3张。不是同一组三张重播，也不是无限实时生图。点击生成前和生成过程中，工作台大图、角度缩略图、顶部预览和融合输入位置都只显示占位，不提前显示预制场景。完成后三张缩略图同时显示，点击任意一张查看大图并采用，只融合所选场景。切换角度保留整组生成结果，但需要重新采用新选中的场景；更换主图或场景提示词会清除整组生成状态，需要重新生成。重复选择同一选项不清除。更换 SKU 保留已生成场景。旧版记录默认未生成场景，但保留已有交付记录。

第一步提供指定的两张原主图：深色为 `51eeb958ecee9ce30a3b5d83e4182418.jpg`，浅色为 `db087eba82c8fa0863a03e5ef9d2d2d5.jpg`，默认浅色。选图会固定后续深浅风格，第三步不再提供跨风格切换；第二步自有 SKU 不变。也可上传不超过 3 MB 的 JPG、PNG、WebP；图片在浏览器验证可读取后用于预览，随本地演示记录保存。参考主图和 SKU 独立，更换主图会清除当前候选，但不会覆盖 SKU 或已完成作品。若浏览器存储空间不足，顶部会提示仅当前页面保存。上传用于展示参考输入，本次仍采用已预制的场景与融合图，不会按新主图实时重绘。每批三个角度可自由选择，深浅风格只由第一步决定。非指定文件的自定义上传继承当前风格，暂不自动识别。

生成场景后，预览下方的“生成首图并查看”也可直接采用该场景并进入交付。最后一步始终可打开：场景未生成时不显示场景图片，并提供“先生成场景”入口；已有场景时显示两张输入图片和“演示生成首图”入口。融合会播放约 5 秒的四阶段动画（读取产品与场景、对齐地毯角度与位置、融合纹理光线与阴影、整理无字首图），结束后自动显示最终图片和保存按钮。两种进度百分比均为演示动画；可重播，重新演示或离开当前案例会取消计时。SKU 02–04 在有场景后可显式切换 SKU 01 体验融合。

每种风格均使用 `22/所有主图案例` 的六张原图角度。深色第一批为 `51eeb…`、`3518…`、`90b2…`，第二批为 `db087…`、`8910…`、`8eed…`；浅色批次顺序相反，家具均统一成浅色。共十二张场景图与十二张 SKU 01 融合图，均预制为无字的 1254×1254 PNG。场景以参考图的地毯角度、位置、透视为约束，AI 输出不是像素级复刻。场景模板与融合成图按深浅方案、角度分别对应。

当前完整融合演示只支持 SKU 01（黑边米白款）；SKU 02–04 可选产品、确认、选场景，但暂未制作对应融合成图。采用场景后，可点击明确标注的“切换 SKU 01 并继续融合”，保留当前深浅方案与角度、切换产品后直接播放生成演示，不会将 SKU 01 成图标为其他款式。实际切换产品或场景会清除候选并要求重新采用场景；重复点当前角度保留采用状态。重新生成会清除采用状态与未保存候选，但不删除已完成首图；第二批也有逐张对应的融合图。刷新保留批次，中途刷新重试不会跳过未完成的一批。融合按钮旁会说明尚未采用或提示词为空的原因，避免无提示地无法继续。已交付作品仍保留。33 不预填已完成作品；旧记录中的原主图/无字参考图不会再被当作自有产品成品。“已完成首图”只展示点击“完成并保存首图”确认过的自有产品融合结果；未确认的候选不进入列表，不再预填深古木案例。

修改两个提示词会保存到方案与交付记录，但模拟按钮只加载预制图片，不调用模型或按新提示词重绘。详情可查看记录并下载 PNG/JPG；亮度滑杆仅改变预览，下载仍为原文件。店铺、价格、人员和测试指标为演示假数据。

当前两套主图、六张原始参考图、十二张场景与十二张融合图保存在 `public/demo/source-sets/`，`source-sets/prompts.json` 与 `source-sets/prompts-batch-2.json` 分别记录两批素材来源和内置 image_gen 制作提示词。来源文件与第二步 SKU 素材保持不变。`public/demo/user-33/`、`public/demo/user-22/` 和旧 `public/demo/own-scenes/` 仍保留供原案例及历史交付使用。完整演示不需要 Supabase、JMR 或 API Key，不会上传到云数据库。

当前项目进度、提示词和最近一次交付记录保存在本浏览器的 `carpet-hero-user-images-v2-33`，刷新后可继续。旧的 `carpet-hero-user-images-v2-22` 记录不删除、不展示；若旧缓存曾停留在该案例，重新打开进入自有SKU项目。再次完成交付会替换该案例上一条记录。点击“重新演示”恢复当前案例的初始数据，并清除该案例的演示进度与交付记录。此前蓝花案例的本地记录保留在旧存储键中。

## 5. 测试与构建

```powershell
pnpm test
pnpm build
pnpm build:api
```

真实 JMR 双图合约测试默认跳过，因为每次会产生一次正式模型请求和积分消耗。需要验证时显式设置：

```powershell
$env:ENABLE_JMR_CONTRACT_TEST='true'
$env:JMR_CONTRACT_SCENE_PATH='一张本地场景图片的绝对路径'
pnpm vitest run server/providers/jmr-image.contract.test.ts
Remove-Item Env:ENABLE_JMR_CONTRACT_TEST,Env:JMR_CONTRACT_SCENE_PATH
```

## 安全说明

- Supabase Secret Key 和 JMR Key 不会返回前端。
- Storage Bucket 为私有，浏览器只使用短期签名上传与读取地址。
- 日志不记录密钥、完整签名 URL 或图片 Base64。
- 如果密钥泄露，应立即在对应平台撤销并重新创建。

“风格与场景库”独立展示最初提供的六张原始案例图（`22/所有主图案例` 的原文件副本），深色参考和浅色参考各三张，原有文字保留，缩略图完整显示，可点击查看原图。这里不是生成候选，不受工作台生成状态、风格或批次限制，也不改变工作台选图与融合逻辑。
